# Бот погоды для Telegram

Бот на русском языке с двумя сценариями:

1. **Подписка на ежедневную рассылку.** `/start` → кнопка «Начать» →
   выбор города кнопками → выбор времени кнопками → готово. Каждый день
   в выбранное время бот сам присылает погоду в выбранном городе
   (время — местное для этого города, не время сервера).
2. **Разовая проверка погоды.** `/weather <город>`, просто написать
   название города текстом, или написать фразу вроде «отправь погоду» /
   «какая погода» без города — тогда бот пришлёт погоду по городу твоей
   подписки (если ты уже подписан через `/start`).

Данные берутся с Open-Meteo — бесплатно, без API-ключа и регистрации.
Подписки хранятся в JSON-файле на диске, поэтому переживают перезапуск бота.

## Файлы проекта

- `bot.py` — команды, кнопки, планирование рассылки
- `weather.py` — запросы к Open-Meteo (геокодинг + текущая погода)
- `cities.py` — список городов для кнопок (координаты + таймзона)
- `storage.py` — хранение подписок в `subscriptions.json`
- `requirements.txt` — зависимости
- `.env.example` — пример файла с токеном
- `Dockerfile`, `docker-compose.yml` — запуск в контейнере на сервере

## Команды бота

| Команда | Что делает |
|---|---|
| `/start` | Подписаться на рассылку (или изменить город/время, если уже подписан) |
| `/status` | Показать текущую подписку |
| `/stop` | Отписаться от рассылки |
| `/weather <город>` | Узнать погоду прямо сейчас, разово |
| `/help` | Список команд |

Также можно просто написать «отправь погоду» или «какая погода» без
названия города — бот пришлёт погоду по городу подписки.

Города в кнопках выбора (`cities.py` → `CITIES`): Москва, Санкт-Петербург,
Новосибирск, Шымкент, Казань, Нижний Новгород, Челябинск, Самара, Астана,
Ростов-на-Дону. Время рассылки — `TIME_SLOTS`. Если нужен другой город или
время — отредактируй эти списки (для города нужны широта, долгота и
IANA-таймзона).

> Про Шымкент и Астану: с 1 марта 2024 года Казахстан перешёл на единый
> часовой пояс UTC+5 по всей стране, поэтому оба города используют зону
> `Asia/Almaty` — это отражено в `cities.py`.

## Шаг 1. Получить токен бота

1. В Telegram открой чат **@BotFather**.
2. Отправь `/newbot` и следуй подсказкам (укажи имя и username бота,
   username должен заканчиваться на `bot`, например `my_weather_bot`).
3. BotFather пришлёт токен вида `123456789:AAExample...` — сохрани его,
   он понадобится дальше.

## Шаг 2. Запустить локально (чтобы проверить, что всё работает)

```bash
cd weather_bot
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt

export TELEGRAM_BOT_TOKEN="твой_токен"   # Windows (PowerShell): $env:TELEGRAM_BOT_TOKEN="твой_токен"
python bot.py
```

Открой своего бота в Telegram, напиши `/start`, нажми «Начать», выбери
город и время кнопками. Проверь, что подписка сохранилась (`/status`) и
что `/stop` её убирает. Пока скрипт запущен в терминале — бот работает.
Закроешь терминал — бот остановится, поэтому для постоянной работы
(и чтобы рассылка реально приходила каждый день) нужен деплой на сервер
(шаги 3–4).

## Шаг 3. Перенести код в GitHub

Это подготовительный шаг для обоих вариантов деплоя ниже (и просто хорошая
практика — код не пропадёт, если что-то случится с твоим компьютером).

1. Создай пустой репозиторий на github.com (кнопка **New repository**,
   без README/gitignore — они не нужны, у нас всё уже готово).

**Без терминала (проще всего, через сайт):**

2. Если ещё не распаковал(а) присланный архив `weather_bot.zip` — сделай
   это сейчас (на Windows: правая кнопка → «Извлечь всё», на Mac: двойной
   клик по архиву). Должна получиться папка с файлами `bot.py`,
   `weather.py`, `cities.py` и т.д. — не архив, а именно файлы.
3. На странице своего нового репозитория на GitHub нажми
   **Add file → Upload files** (или ссылку «uploading an existing file»,
   если её сразу предлагают).
4. Перетащи туда ВСЕ файлы из папки `weather_bot` (не саму папку, а её
   содержимое — `bot.py`, `weather.py`, `cities.py`, `storage.py`,
   `requirements.txt`, `Dockerfile`, `docker-compose.yml`, `.env.example`,
   `.dockerignore`, `README.md`).
5. Внизу нажми **Commit changes**. Готово — код в GitHub.

**Через терминал (если умеешь пользоваться git):**

```bash
cd weather_bot
git init
git add .
git commit -m "Weather bot"
git branch -M main
git remote add origin https://github.com/ТВОЙ_ЛОГИН/НАЗВАНИЕ_РЕПОЗИТОРИЯ.git
git push -u origin main
```

6. Токен бота **никогда** не клади в код или в публичный репозиторий — он
   передаётся только через переменную окружения. Файл `.env` с настоящим
   токеном создавай уже на сервере (следующий шаг), в GitHub он не должен
   попасть — в репозитории есть только `.env.example` с примером.

## Шаг 4. Деплой для круглосуточной работы

Готового «единственно верного» варианта нет, поэтому вот два нормальных пути:

### Вариант А — свой VPS + Docker (надёжнее всего, полный контроль)

Подходит, если не против взять недорогой VPS (обычно от ~150–300 ₽/мес,
например Timeweb Cloud, Selectel, Hetzner) и один раз настроить.

1. Установи Docker на сервере:
   ```bash
   curl -fsSL https://get.docker.com | sh
   ```
2. Склонируй репозиторий на сервер:
   ```bash
   git clone https://github.com/ТВОЙ_ЛОГИН/НАЗВАНИЕ_РЕПОЗИТОРИЯ.git
   cd НАЗВАНИЕ_РЕПОЗИТОРИЯ
   ```
3. Создай `.env` на основе `.env.example` и впиши туда токен:
   ```bash
   cp .env.example .env
   nano .env   # вставь TELEGRAM_BOT_TOKEN=твой_токен
   ```
4. Запусти:
   ```bash
   docker compose up -d --build
   ```
5. Проверка, что бот жив:
   ```bash
   docker compose logs -f
   ```
   Благодаря `restart: unless-stopped` в `docker-compose.yml` бот сам
   поднимется после перезагрузки сервера или падения. Файл подписок
   лежит в `./data/subscriptions.json` на хосте (примонтирован как volume),
   поэтому переживает пересборку контейнера.

Обновление кода в будущем: `git pull` → `docker compose up -d --build`.

### Вариант Б — облачный PaaS (Railway / Render), без своего сервера, без терминала

Проще для старта, не нужно администрировать сервер — почти всё делается
кликами в браузере. На примере Railway.app:

1. Репозиторий на GitHub уже готов (шаг 3).
2. Зайди на railway.app, зарегистрируйся через свой аккаунт GitHub.
3. **New Project → Deploy from GitHub repo** → выбери свой репозиторий
   (Railway попросит один раз авторизовать доступ к GitHub — подтверди).
4. Railway сам увидит `Dockerfile` в репозитории и соберёт бота по нему —
   ничего дополнительно указывать не нужно.
5. Открой созданный сервис → вкладка **Variables** → добавь переменную
   `TELEGRAM_BOT_TOKEN` со значением твоего (нового!) токена от BotFather.
6. Чтобы подписки не терялись при каждом обновлении — вкладка
   **Settings → Volumes** → добавь volume с mount path `/app/data`, и в
   Variables пропиши `SUBSCRIPTIONS_FILE=/app/data/subscriptions.json`.
7. Дождись, пока сборка завершится (вкладка **Deployments**), затем
   открой вкладку **Logs** — там должна появиться строка
   «Бот запущен, ожидаю сообщения...». Значит бот работает.

С Render.com шаги аналогичные (New → Web Service → из GitHub-репозитория,
переменные окружения — в разделе Environment), но постоянный диск на
бесплатном тарифе может отсутствовать — уточни на сайте перед стартом.

Условия бесплатных тарифов у этих сервисов периодически меняются, так что
перед стартом стоит свериться с текущими лимитами на их сайтах.

**Если пока не уверен, что выбрать:** начни с локального запуска (шаг 2),
чтобы убедиться, что бот работает и отвечает как нужно, а для
постоянной работы — самый предсказуемый вариант это VPS + Docker (вариант А):
меньше сюрпризов с потерей подписок и лимитами бесплатных тарифов, плюс
полностью твой контроль.

## Как проверить, что бот реально «заработал» после деплоя

Отдельно «переносить бота в Telegram» не нужно — он уже подключён к
Telegram через токен от BotFather, и как только процесс (в контейнере или
на PaaS) запущен и подключён к интернету, он сам начинает получать
сообщения. Проверка:

1. Открой своего бота в Telegram по его username (тот, что задавал в BotFather).
2. Напиши `/start` — если ответил, бот работает.
3. Подпишись через кнопки, затем в назначенное время рассылки проверь
   логи (`docker compose logs -f` или вкладка Logs на Railway/Render) —
   там будет видно попытку отправки, и само сообщение придёт в чат.

## Как это работает технически (коротко)

- При выборе города и времени бот вычисляет таймзону города (`cities.py`)
  и ставит задачу через `JobQueue` (`run_daily`) с этой таймзоной — поэтому
  рассылка приходит по местному времени города, а не по времени сервера.
- При перезапуске бота (`post_init` в `bot.py`) все подписки из
  `subscriptions.json` перечитываются и задачи регистрируются заново —
  рассылка не «теряется» после рестарта или обновления бота.
- `/stop` снимает задачу из `JobQueue` и удаляет запись из хранилища.

## Возможные проблемы

- **Бот не отвечает** — проверь, что процесс/контейнер запущен
  (`docker compose logs -f`) и что токен верный (без лишних пробелов).
- **Рассылка не приходит** — проверь `/status`, что подписка активна;
  посмотри логи на момент нужного времени — там будет видно, если запрос
  к Open-Meteo не прошёл.
- **«Не нашёл город»** (для `/weather`) — Open-Meteo иногда лучше находит
  город по английскому названию (например `Saint Petersburg` вместо
  `Санкт-Петербург`) — в таком случае просто попробуй написать иначе.
- **Нужен город не из списка кнопок** — добавь его в `CITIES` в `cities.py`
  (нужны широта, долгота и IANA-таймзона, например `Europe/Moscow`).

## Про этичное использование рассылок

Бот присылает сообщения только тем, кто сам явно нажал «Начать» и выбрал
город/время — это осознанная подписка, а не рассылка без согласия. Команда
`/stop` всегда доступна и сразу останавливает сообщения. Если планируешь
делиться ботом с другими людьми, стоит и дальше держаться этого принципа:
не подписывать людей без их действия и не усложнять отписку — это и
корректно по отношению к пользователям, и требование самого Telegram
(рассылка непрошеных сообщений через ботов — нарушение правил платформы
и может привести к блокировке бота).
